# 智能暂停与开机自启 设计确认稿

> 本文档为两特性设计拷问后的确认结果，作为实现依据。

---

## 一、开机自启（Launch at Login）

### 1.1 实现方式

- `SMAppService.mainApp`（macOS 13+ 原生 API，项目目标 macOS 14+，非沙盒可用）。
- 真相源（source of truth）= `SMAppService.mainApp.status`，**不**在 `AppConfig` 里冗余存布尔，避免与系统状态失同步。

### 1.2 默认值与首次启动

- 默认**关闭**，不静默开启。
- 首次启动弹窗询问：用 `UserDefaults` 标记位 `WallFlux.didShowLaunchAtLoginPrompt` 判断是否首启；弹窗内含勾选项「开机自启」，用户主动决定。
- 首次启动若电量偏低且智能暂停已触发，弹窗应同时简述当前暂停状态，避免用户困惑。

### 1.3 开关位置

- 菜单栏面板 + 全局设置「启动」分区**都有**，双向同步。

### 1.4 状态同步

- 面板 / 设置视图 `onAppear` 时读取 `SMAppService.mainApp.status` 刷新开关真实状态，**不做定时轮询**。
- 用户点开关时写穿：ON → `register()`；OFF → `unregister()`。

### 1.5 审批状态呈现（`.requiresApproval`）

| 系统状态                           | 开关显示 | 附加 UI                                                                                                    |
| ------------------------------ | ---- | -------------------------------------------------------------------------------------------------------- |
| `.enabled`                     | 亮（开） | 无                                                                                                        |
| `.requiresApproval`（已注册但系统未批准） | 亮（开） | 警示文案「需在系统设置中批准」+「打开系统设置」按钮（deeplink `x-apple.systempreferences:com.apple.LoginItems-Settings.extension`） |
| `.notRegistered` / `.notFound` | 灭（关） | 无                                                                                                        |

## 二、智能暂停与节能条件（Smart Pause）

### 2.1 响应模型

- **二值暂停**：任一启用条件命中 → 完全暂停（停播放 + 停微跳）。无"降频"中间态。
- 取舍已确认：电池供电等场景下微跳一并停止，防烧屏能力暂时让位给节能。

### 2.2 暂停源模型（核心架构）

- 手动暂停与智能暂停为**两个独立暂停源**，OR 在一起：任一为真即暂停。
- 每个 `ScreenContext` 维护一个**暂停源集合**：
  - 全局源：系统睡眠 / 低电量模式 / 电池供电 / 低电量阈值 / 显示器睡眠（命中即作用于所有屏）。
  - 单屏源：全屏应用（仅作用于命中的那台屏）。
  - 集合非空 → 该屏暂停。
- 智能暂停命中时面板 / 设置显示原因（如「已暂停：电池供电」），与手动暂停的「已暂停」区分。

### 2.3 条件清单（共 6 个，默认全部启用）

| 条件    | 作用域 | 监听方式                                                                                 | 默认 |
| ----- | --- | ------------------------------------------------------------------------------------ | -- |
| 系统睡眠  | 全局  | `NSWorkspace.willSleepNotification`                                                  | ON |
| 显示器睡眠 | 全局  | `CGDisplayRegisterReconfigurationCallback` 检测 blanking / IORegisterForSystemPower    | ON |
| 低电量模式 | 全局  | `ProcessInfo.processInfo.isLowPowerModeEnabled` + `NSProcessInfoPowerStateDidChange` | ON |
| 电池供电  | 全局  | `IOPSNotificationCreateRunLoopSource` 电源变化通知                                         | ON |
| 低电量阈值 | 全局  | 同电源通知，读 `IOPSCopyPowerSourcesInfo` 电量百分比                                             | ON |
| 全屏应用  | 单屏  | `CGWindowList` 每 2 秒轮询                                                               | ON |

### 2.4 各条件行为细则

**系统睡眠**

- 睡眠前（`willSleepNotification`）：全部屏暂停。
- 唤醒后（`didWakeNotification`）：**重置所有闲置计时器为 active**，按当前条件重新评估恢复。显示器睡眠条件若仍命中（屏仍睡）则保持暂停；用户唤醒显示器（动鼠标/按键）后条件清除即恢复。

**显示器睡眠**

- 屏进入睡眠 → 暂停（壁纸本不可见，仅为省 CPU）。
- 屏唤醒（用户输入触发）→ 条件清除 → 恢复。

**低电量模式**

- 用户开启系统低电量模式 → 暂停；关闭 → 恢复。直接跟随系统状态。

**电池供电**

- 未接电源（`kIOPSPowerSourceStateKey == "Battery Power"`）→ 暂停。
- 接通电源 → 恢复。

**低电量阈值**

- **与电源状态无关**：电量百分比 < 阈值即暂停，插电充电也查（充过阈值 + 滞后才恢复）。(提示电量超过阈值时恢复)
- 阈值**可配**：默认 **40%**，范围 5%–50%，slider 调节。
- **防抖滞后**：暂停线 = 阈值；恢复线 = 阈值 + 5%。避免边界电量波动导致频繁抖动。
- 与「电池供电」独立：两个条件可叠加（电池时被前者停；插电但电量低被后者停），互不冗余。

**全屏应用（per-display）**

- 每 2 秒轮询 `CGWindowList`（`.optionOnScreenOnly`）。
- 判定：存在 layer 0 普通窗口，其 bounds **完全覆盖**某 `NSScreen` 的完整 frame（含菜单栏区域）= 真正的 macOS 全屏。
- **最大化窗口算**（只铺工作区、不含菜单栏区域）。
- 命中的屏单独进入全屏暂停源，其他屏不受影响。
- 全屏退出 → 条件清除 → 该屏恢复（active 屏恢复微跳；idle 屏恢复循环播放）。

### 2.5 手动暂停 vs 智能暂停

- **不允许手动覆盖**智能暂停：智能条件是硬门槛。
- 智能暂停命中时：
  - 面板恢复按钮**灰显**。
  - 旁边提示原因 + 解决指引，如：「已暂停：电池供电。接通电源或前往设置关闭该条件以恢复。」
  - 多条件同时命中时，列出所有命中原因（或最可操作的一个 + 其余折叠）。
- 手动暂停（`CoreManager.isPaused`）与智能暂停独立：用户手动暂停时智能条件照常评估（无影响，反正已停）；用户手动恢复只清手动源，智能源仍生效。

### 2.6 总开关

- 设置「智能暂停」分区顶部放一个总开关 `smartPauseEnabled`：一键禁用整个智能暂停特性（所有条件不再评估），回归纯手动控制。
- 总开关 OFF 时各条件开关保留配置但不生效。

## 三、配置结构变更（`AppConfig`）

新增字段（均需在 `init(from:)` 用 `decodeIfPresent` 回退默认值，兼容旧版本）：

```swift
struct AppConfig {
    // ... 既有字段 ...

    // 智能暂停
    var smartPauseEnabled: Bool = true
    var pauseOnSleep: Bool = true
    var pauseOnDisplaySleep: Bool = true
    var pauseOnLowPowerMode: Bool = true
    var pauseOnBattery: Bool = true
    var pauseOnLowBattery: Bool = true
    var lowBatteryThresholdPercent: Double = 40   // 5...50
    var pauseOnFullscreen: Bool = true
}
```

- 开机自启**不**入 `AppConfig`，`SMAppService` 为真相源。
- 首启标记 `WallFlux.didShowLaunchAtLoginPrompt`（Bool）存 `UserDefaults`。

## 四、状态机影响

`ScreenContext` 现有状态：`active` / `idle` / `exiting`。

新增**暂停态**（叠加于上述状态之上，非替代）：

- 暂停时：停播放 / 停微跳计时器，记录暂停前的状态（active 或 idle）。
- 恢复时：回到暂停前的状态——暂停前是 active 则恢复微跳；暂停前是 idle 则恢复循环播放（从 `lastFramePosition` 续播）。
- 全屏单屏暂停：仅该屏进入暂停态，其余屏不受影响。

---

## 五、UI 布局

- **全局设置**新增两个分区：
  - 「启动」分区：开机自启开关（+ 审批警告 / 跳转按钮）。
  - 「智能暂停」分区：总开关 + 6 个条件开关 + 低电量阈值 slider（仅 `pauseOnLowBattery` 开启时显示）。
- **菜单栏面板**：
  - 状态区显示当前各屏状态；智能暂停命中时显示「已暂停：[原因]」+ 灰显恢复按钮 + 指引提示。
  - 开机自启开关纳入面板快速控制区。
